# 制度文档脱敏工具

把一批 Word 制度文档（`.docx`）按词典脱敏，输出新的 `.docx`。**源文件只读，不会被修改**；全部在本机处理，不联网、不调用任何外部服务。

## 处理了什么

| 位置 | 处理 |
|---|---|
| 正文、表格、文本框、脚注尾注、页眉页脚 | 按词典和格式规则替换文字。一个名称被 Word 拆成多个格式片段（比如半个加粗）也能替换 |
| 修订痕迹 | 全部接受：删除过的文字彻底清除，插入的文字保留；同时关闭「修订」开关 |
| 批注 | 全部删除 |
| 文档属性 | 清空作者、最后修改人、单位、经理、关键词、模板等；标题按词典替换 |
| 超链接地址、图片说明文字、域代码 | 按词典和规则替换 |
| 文件名、文件夹名 | 按词典替换 |
| Word 自动编号、表格、格式、图片 | **保留不动** |

**处理不了、需要人工看的**：图片里的文字（如公章、截图）、嵌入的 Excel 等对象。报告会逐个文件列出数量。

## 安装（Mac，只需一次）

需要 Python 3.9 以上。Mac 打开「终端」，输入 `python3 --version` 能看到版本号即可；提示需要安装开发者工具时，按提示安装。

```bash
cd tools/redact
./run.sh --help
```

第一次运行会在 `tools/redact/.venv` 里自动安装唯一的依赖 `lxml`（需要联网一次）。离线环境：在能联网的 Mac 上执行一次 `./run.sh --help`，再把整个 `tools/redact` 目录（含 `.venv`）拷过去。

## 使用

1. 把 Word 文件放进一个文件夹，比如 `~/制度原件`。可以有子文件夹。`.doc` 文件请先在 Word 里「另存为」`.docx`。建议先在 Word 里接受或拒绝全部修订、删除批注再另存（工具也会处理，人工先看一遍更稳妥）。
2. 准备替换词典，比如 `~/词典.csv`，写法见 [DICTIONARY.md](DICTIONARY.md)，可以从 [`词典示例.csv`](词典示例.csv) 改起。
3. 运行：

   ```bash
   cd tools/redact
   ./run.sh --input ~/制度原件 --dict ~/词典.csv --output ~/脱敏结果
   ```

4. 看结果：

   ```
   ~/脱敏结果/20261124-15/          ← 按「年月日-小时」命名；同一小时再跑一次是 20261124-15-2
   ├── 脱敏文件/                     ← 只有这个目录可以外发，目录结构与原件一致
   └── 内部留存-勿外发/
       ├── 报告.md                   ← 每个文件替换了多少、是否通过复查、需人工检查的项
       └── 对照表.csv                ← 原文 ↔ 替换值（含原文！）
   ```

## 怎么判断结果可以外发

打开 `报告.md`：

- **✅ 通过复查**：工具重新读了一遍输出文件，确认词典里的每个原文、每条格式规则都**不再出现**在任何位置（正文、页眉页脚、属性、链接等）。
- **❌ 需处理**：列出残留的位置，处理后重跑。
- **需人工检查**：有图片或嵌入对象的文件，打开看一眼图片里有没有公司名、公章、签名。
- **疑似遗漏**：形如「××有限公司」「××集团」、但不在词典里的写法。确认是要脱敏的就加进词典，重跑。
- **跳过的文件**：非 `.docx` 文件（如 `.doc`），另存为后重跑。

全部通过、人工检查完，再把 `脱敏文件/` 交出去。**`内部留存-勿外发/` 里有原文，不要外发。**

有任何一个文件「需处理」时，命令以非零状态结束，方便脚本判断。

## 速度

按文件数并行处理（默认使用全部 CPU 核，`--jobs 1` 改为逐个处理），并在终端显示进度和预计剩余时间。实测（4 核 Linux 容器，每份约 500 段正文、带 1 MB 图片）：200 份、212 MB 用时约 5 秒。耗时主要取决于**文件份数和正文长度**，图片大小影响很小。

```bash
python3 -m unittest discover -s tests
```
