# 制度文档脱敏工具

把一批 Word 制度文档（`.docx`）按词典脱敏，输出新的 `.docx`，并为原件和脱敏后的文件各生成一份 Markdown（`.md`）。**源文件只读，不会被修改**；全部在本机处理，不联网、不调用任何外部服务。

## 处理了什么

| 位置 | 处理 |
|---|---|
| 正文、表格、文本框、脚注尾注、页眉页脚 | 按词典和格式规则替换文字。一个名称被 Word 拆成多个格式片段（比如半个加粗）也能替换；中文字之间为对齐加的空格（「张 三 丰」）不影响匹配，词典里写「张三丰」即可 |
| 修订痕迹 | 全部接受：删除过的文字彻底清除，插入的文字保留；同时关闭「修订」开关 |
| 批注 | 全部删除 |
| 文档属性 | 清空作者、最后修改人、单位、经理、关键词、模板等；标题按词典替换 |
| 超链接地址、图片说明文字、艺术字、域代码 | 按词典和规则替换 |
| 图表标签、SmartArt 文字、自定义 XML 数据 | 按词典和规则替换 |
| 文件名、文件夹名 | 按词典替换 |
| Word 自动编号、表格、格式、图片 | **保留不动** |

**处理不了、需要人工看的**：图片里的文字（如公章、截图）、嵌入的 Excel 等对象。报告会逐个文件列出数量。

## 安装（Mac，只需一次）

需要 Python 3.9 以上。Mac 打开「终端」，输入 `python3 --version` 能看到版本号即可；提示需要安装开发者工具时，按提示安装。

```bash
cd tools/redact
./run.sh --help
```

第一次运行会在 `tools/redact/.venv` 里自动安装唯一的依赖 `lxml`（需要联网一次）。离线环境：在能联网的 Mac 上执行一次 `./run.sh --help`，再把整个 `tools/redact` 目录（含 `.venv`）拷过去。

## 使用

1. 把 Word 文件放进一个文件夹，比如 `~/制度原件`。可以有子文件夹。有 `.doc`、`.rtf`、`.wps` 等旧格式时，先按下文[转换旧格式](#转换旧格式doc--rtf--wps)单独转一次（就地生成同名 `.docx`）。建议先在 Word 里接受或拒绝全部修订、删除批注再另存（工具也会处理，人工先看一遍更稳妥）。
2. 准备替换词典，比如 `~/词典.csv`，写法见 [DICTIONARY.md](DICTIONARY.md)，可以从 [`词典示例.csv`](词典示例.csv) 改起。建议先用「扫描」自动找出候选词，见下文[先扫描出候选词](#先扫描出候选词)。
3. 运行：

   ```bash
   cd tools/redact
   ./run.sh --input ~/制度原件 --dict ~/词典.csv --output ~/脱敏结果
   ```

4. 看结果：

   ```
   ~/脱敏结果/20261124-15/          ← 按「年月日-小时」命名；同一小时再跑一次是 20261124-15-2
   ├── 脱敏文件/                     ← 只有这个目录可以外发，目录结构与原件一致
   │   ├── 甲公司差旅办法.docx        ← 完整文件（含附件），是正式文本
   │   ├── 甲公司差旅办法.md          ← 脱敏后的 Markdown：正文，不含附件
   │   └── 甲公司差旅办法-附件/       ← 有附件时才有：每个附件一个 .docx（可直接下载填写）和一个 .md
   │       ├── 附件1-出差申请单.docx
   │       └── 附件1-出差申请单.md
   └── 内部留存-勿外发/
       ├── 原件md/                   ← 原件的 Markdown（含原文！），文件名与原件相同，附件同样拆开
       ├── 报告.md                   ← 替换汇总、未命中的词条、每个文件是否通过复查、需人工检查的项
       ├── 替换汇总.csv              ← 每个词条 / 规则共替换了几处、涉及几个文件（含原文！）
       └── 对照表.csv                ← 每个文件每处替换：原文 ↔ 替换值（含原文！）
   ```

   原件本身不复制，仍在 `--input` 目录里。不需要 Markdown 时加 `--no-md`；不拆附件时加 `--no-split`。

## 转换旧格式（.doc / .rtf / .wps）

扫描和脱敏只处理 `.docx`。有旧格式文件时，先单独转换一次：

```bash
./run.sh convert --input ~/制度原件
```

- **就地转换**：`a.doc` 旁边生成同名的 `a.docx`，`a.doc` 保留不动。之后扫描和脱敏的 `--input` 仍然是 `~/制度原件`；旁边已有同名 `.docx` 的 `.doc` 会被自动忽略，只处理 `.docx`。
- **不覆盖已有文件**：同一文件夹里已经有同名 `.docx`（比如人工另存过的版本）的，不转换、不覆盖，在报告里列出。确实要重新转换并覆盖，加 `--overwrite`。所以重复运行是安全的：新增的 `.doc` 才会转换。
- 不想写进原件文件夹，可以加 `--output ~/制度原件-docx`：转到另一个文件夹，原来的 `.docx` 也复制过去，之后扫描和脱敏用这个文件夹。
- 转换用 LibreOffice（推荐，需安装，`.wps` 只能用它转）；没装时用 Mac 自带的 textutil，但会丢页眉页脚。扩展名是 `.doc`、其实是 `.docx` 的文件直接更正扩展名。
- 原件文件夹旁边生成 `制度原件-转换报告-<时间>.md`：转换了哪些、失败了哪些（加密或损坏的文件，请在 WPS / Word 里手动另存为同名 `.docx`）、哪些因已有同名 `.docx` 没转、哪些 PDF / 图片等没有处理。
- **转换后先抽查**：挑几份有红头、表格、自动编号、印章的，用 WPS 打开和原件对比。

## 先扫描出候选词

人工整理关键词容易漏。先扫描一遍原件，生成一份候选词典，人工确认后再脱敏：

```bash
./run.sh scan --input ~/制度原件 --output ~/脱敏结果
# 已有词典时加 --dict，已列过的词不再出现：
./run.sh scan --input ~/制度原件 --dict ~/词典.csv --output ~/脱敏结果
```

有 `.doc` 等旧格式文件时，先[转换](#转换旧格式doc--rtf--wps)，再扫描。

结果在 `~/脱敏结果/<年月日-小时>-扫描/`：

- `候选词典.csv`：格式与正式词典相同，「替换为」已填好；同一机构的全称和简称填的是同一个替换值。备注里有置信度、出现次数、文件数和一句上下文。**置信度低的行类别前带 `#`，默认不生效**，确认要用就删掉 `#`；不要的行整行删除。确认完可以直接当词典用，或并入正式词典。
- `扫描报告.md`：按类别列出全部候选。

| 类别 | 怎么找 | 置信度 |
|---|---|---|
| 集团 / 公司 / 机构 | 名称 + 有限公司、集团、银行、研究院、事务所等后缀；带法定后缀的全称会自动推出简称（「K市M集团有限责任公司」→「K市M集团」「M集团」），只列文档里真出现过的 | 全称、简称高；没有法定后缀的普通说法（「汽车租赁公司」）低 |
| 地名 | ××省 / 市 / 县 / 区 / 镇 | 出现在机构名里的（能指认公司所在地）高；北京、上海等常见省市低 |
| 人名 | Word 记录的作者、修订人、批注人；「签发人：」「联系人：」这类角色词后面的姓名（不限姓氏，字间带对齐空格的「张 三 丰」也能找到；表格里「经办人｜张三」分在两格的也算）；「××总经理」「××同志」这类职务前面的常见姓氏姓名 | 高 / 中 |
| 文号 | 「代字〔年份〕序号号」里的机关代字（如 HDGO、HDB字），替换它整条文号就认不出单位了 | 高 |
| 编号 | 多段连字符、含字母和数字的编码（制度编码、合同编号） | 中 |
| 缩写 | 编码开头的中文简称（「华集」）；独立的英文大写缩写 | 中 / 低 |
| 系统 | ××系统 / ××平台 / ××OA | 低 |
| 地址 | …路 / 街 + 门牌号 | 高 |
| 域名 | 网址、邮箱里的单位域名（取主域名，覆盖所有子域名） | 中 |

**扫描找不到、需要人工补的**：没有职务或角色词提示的人名（名单、签名）、项目名、产品和品牌名、客户和供应商的简称、图片里的文字。手机号、身份证号、银行卡号、邮箱、网址由 `patterns.csv` 的格式规则直接替换，不用写进词典。

扫描和脱敏一样只在本机运行、不联网。原件涉及保密协议时，不要把原件发到任何在线服务上扫描。

## 统计 Markdown 大小

每次脱敏结束时自动统计；对已有的结果单独统计：

```bash
./run.sh stats --input ~/脱敏结果/20261124-15
```

终端打印合计和按大小排好的前 10 份。结果目录下生成：

- `Markdown统计.csv`：**每份制度一行**（正文和附件合计），已按 token 从大到小排好，第一列是排名，Excel 打开即可看。
- `Markdown统计.md`：同样的排名，加上合计和阈值说明。
- `Markdown明细.csv`：每个 `.md` 一行，也按大小排。

- token 估算与系统里版本文档的口径一致（`src/data/document-text.ts`）：字符数（含 Markdown 标记）÷ 1.5，向上取整。只用于判断篇幅。
- 标出两个阈值：单份制度超过 1.2 万 token 的（问这份制度时改为段落检索）；全部合计是否超过 2.4 万 token（不超过时通用问可以全部放入）。
- 统计只读脱敏后的文件，结果里的文件名也是脱敏后的。

## 打包与导入系统

脱敏确认无误后，两步把制度写进 BrightRule 系统（本机运行，经系统的 HTTPS 接口写入，云环境同样适用）：

```bash
./run.sh package --run ~/脱敏结果/20261124-15                             # 打包（文件用脱敏后的 docx）
./run.sh import --package 导入包/20261124-15 --url https://<系统地址> --login          # 预演：输入账号密码，只列计划
./run.sh import --package 导入包/20261124-15 --url https://<系统地址> --login --apply  # 写入
```

**打包**（`package`）读「脱敏文件」，生成 `导入包/<时间>/`。**默认正文、附件都只进脱敏 Markdown，不上传任何文件，导入包里也没有原文**。附件（附表、表单）要另带脱敏后的 docx 供员工下载时加 `--files attachments`；正文也带时加 `--files redacted`；上传原件时加 `--originals ~/制度原件 --files original`。

**图片不进系统**：Markdown 里没有图片。图片、图表、SmartArt、公式、嵌入对象的内容在原位置只留「（图片）」「（图表）」「（SmartArt 图形）」「（公式）」「（嵌入对象）」标记，问询时模型看不到。打包时按份统计，写进批次清单「问题」一栏和检查报告「含图片等非文字内容」一节；流程图、扫描的表格等重要内容请对照原件写成文字。只有图片、没有文字的附件不导入。

- `批次清单.csv`：每份制度一行，预填制度编号、名称、版本号（文号，没有时填 V1.0）、生效日期、发文日期、类别、层级、发文单位、归口部门，「问题」一栏写明缺条、重复、缺字段。制度名称、版本号必须有；制度编号、生效日期原文没有的可以留空（没有编号的制度按名称对应）。**人工核对后再导入**，导入以它为准；不导入的行把「导入」改成「否」。
- `检查报告.md`：每份的元数据、条号问题、附件分类、超长提示；被拒绝打包的文件（脱敏复查未通过、找不到原件）。
- 每份制度一个文件夹：`manifest.json`、`正文.md`、`附件N.md`（按 `--files` 还有 `附件N.docx`、`正文.docx`）。
- 口径与系统的版本文档一致：字数 = 脱敏正文的码点数；token = 字数 ÷ 1.5；条号索引每条 `{article, chapter, redacted: [起, 止)}`；内容哈希 = 上传的那个文件字节的 SHA-256；不传文件的取脱敏 Markdown 的 SHA-256。正文末尾的附件清单不进正文。
- 附件分类：表格里空格子占 40% 以上 → 表单；没有文字 → 仅原件；其余 → 规范性。
- 制度名称、文号等元数据：不给原件目录时取脱敏后的写法（与正文一致）；给了 `--originals` 默认取原文，`--meta redacted` 可改回脱敏写法。
- 用 `--files original` 或 `--meta original` 时**导入包含原件或原文**，和「内部留存-勿外发」一样不能外发、不能进 Git。

**导入**（`import`）按批次清单里「导入 = 是」的行：制度（按编号找，没有就建草稿）→ 版本（按制度 + 版本号找，没有就建草稿）→ 版本文档（上传原件，写入脱敏正文和条号索引）。

- 默认只预演，加 `--apply` 才写入；写完在导入包里留一份导入报告。
- 同一批导两次结果不变；版本还是草稿时只更新有变化的文档。
- **版本已是现行而内容有变化，整行拒绝**：请在批次清单里改用新版本号（如新的文号）再导入。只是上传的文件变了（如改为正文不传 docx），现行版本也可以直接更新；导入包里没有文件的文档，系统里原有的文件会被去掉。
- 导入的版本都是草稿：管理员在系统里核对后设为「现行」，旧版本自动失效，员工才能看到、问到。
- **制度类别**取自制度信息表的「制度类别」，导入时对应到系统的 12 个分类（公司治理类、战略投资类、经营管理类、人力资源管理类、财务管理类、资产管理类、审计合规类、安全环保监管类、科技与工程管理类、数字化管理类、党工纪类、综合行政类）：先比完全相同，再比去掉「（管理 / 监管）类」后的核心词（「经营类」→ 经营管理类），对不上的不填并提示。
- **登录**：用 `--login`，运行时输入制度管理员的邮箱和密码（密码不回显、不保存；可用环境变量 `BRIGHTRULE_EMAIL` 免输邮箱）。平台的文件上传只认登录会话，**API Key（`BRIGHTRULE_API_KEY`）只能查询和写记录，传不了文件**；也可用 `BRIGHTRULE_TOKEN` 给登录会话令牌。凭证被拒（401）时整批停下并提示，不会每行都报一遍。
- 中途失败重跑即可：已写入的会跳过，没写完的（如制度、版本建好了但文件没传上）接着做。

**发布**：导入的版本都是草稿。核对后可以在系统「制度维护 → 待发布版本」里勾选多条，点「设为现行」；也可以用 `publish` 命令把这个导入包的版本一次全部设为现行：

```bash
./run.sh publish --package 导入包/20261124-15 --url https://<系统地址> --login          # 预演
./run.sh publish --package 导入包/20261124-15 --url https://<系统地址> --login --apply  # 发布
```

- 只处理批次清单里「导入 = 是」的行；暂不发布的行把「导入」改成「否」，或之后在页面上单独设。
- 草稿 → 现行：系统随之把版本文档设为现行、把同一制度原来的现行版本改为已失效、草稿制度改为已发布，员工从此能看到、问到。
- 已是现行的跳过，已失效的不动；系统里的文档比导入包少（导入没做完）的拒绝，先重跑 `import`。

**删除**（`remove`）：删掉制度及其版本、版本文档、条款、关系。系统不允许在页面上直接删还有版本、条款的制度，用这个命令按顺序删：

```bash
./run.sh remove --url https://<系统地址> --login --samples                  # 预演：开发环境自带的 5 份示例制度
./run.sh remove --url https://<系统地址> --login --policy-no 编号 --title 名称   # 预演：指定的制度（可写多次）
```

末尾加 `--apply` 才真正删除，删除不可恢复（导入包还在的话，重跑 `import` 可以再导入）。示例制度只在开发、测试环境加载，生产环境没有；删掉后重启也不会再出现。

## 附件怎么拆

正文之后**单独一行**的「附件」「附件1」「附件 2：」是附件的起点，下一行是附件标题（用作文件名）；每个附件到下一个附件、或到文末版记（「……印发」「抄送：」）为止。表格后面的「备注」属于附件，版记归正文。

- 正文里「附件：1.审批表 2.清单」这一行是附件目录，不是起点，留在正文。
- 拆出的 `.docx` 保留原文件的样式、表格和页面设置，去掉嵌入字体（几十 KB）。
- 报告里逐个文件列出拆出了哪些附件、各含几个表格。附件写法不同（比如没有单独的「附件1」一行）就不会拆，报告里该文件没有「拆出附件」一行，人工看一眼即可。

## Markdown 是怎么转的

转的是阅读和导入用的正文，不是排版：

- **各部分用一级标题标出来**，只看 md 也知道哪段是什么：

  ```
  # 发文通知        红头、文号、「关于印发…的通知」、主送、落款（文件不是发文通知时叫「# 文件开头」）
  # 制度信息        制度信息表（第一列有「制度名称 / 制度编码 / 制度类别…」的表格）
  # 正文：××办法    制度标题之后的章（##）、节（###）、条（**第X条**）
  # 版记            「……印发」「抄送：」
  # 附件（已拆分为单独文件）   附件清单；每个附件文件开头是「# 附件1：××表」
  ```

  认不出章和条的文件不加这些标识，按原样输出。

- **目录页整体去掉**：目录只有标题和页码，对问答没有帮助，还会被检索命中、被当成章标题。识别 Word 自动目录（目录样式、跳到标题的链接、目录控件）和手写目录（「目录」二字之后一串「标题 + 页码」）。

- **文字不会被拆散**：Word 常把一句话甚至一个词拆成好几个格式片段（换字体、半个加粗、拼写检查标记都会拆），工具按段落把片段拼回完整文字再输出。
- **自动编号写成文字**：Word 自动生成的「第一条」「（一）」「1.」不在正文里，直接复制会丢；工具按编号定义算出来写进去。
- 「第X章」→ 二级标题，「第X节」→ 三级标题，Word 标题样式 → 对应级别；「第X条」的条号加粗，方便后续逐条拆分导入。
- 表格 → Markdown 表格，合并单元格展开为空格子；文本框里的文字单独成段，不重复。
- 修订按「全部接受」读取，批注、页眉页脚不输出；图片、图表、SmartArt、公式、嵌入对象写成「（图片）」「（图表）」等标记（内容不转成文字）；脚注放在文末。
- 脱敏后的 `.md` 也参加泄漏复查。

## 怎么判断结果可以外发

终端最后会显示总数，例如「共替换 1234 处：词典 980 处（56/60 个词条命中），格式规则 254 处。4 个词条未命中，见报告。」

打开 `报告.md`：

- **替换汇总**：每个词条、每条规则替换了几处。**未命中的词条**要核对：可能是写法和文件里不一致（错字、全半角、空格），也可能只出现在被删除的修订里，或总是出现在更长的全称里（这两种属正常）。
- **✅ 通过复查**：工具重新读了一遍输出文件，确认词典里的每个原文、每条格式规则都**不再出现**在任何位置（正文、页眉页脚、属性、链接等）。
- **❌ 需处理**：列出残留的位置，处理后重跑。
- **需人工检查**：有图片或嵌入对象的文件，打开看一眼图片里有没有公司名、公章、签名。
- **疑似遗漏**：形如「K市M集团」「××有限公司」、但不在词典里的写法。确认是要脱敏的就加进词典，重跑。「按照集团」「各子公司」这类前面只是普通词语的通用称呼不提示。
- **跳过的文件**：非 `.docx` 文件（如 `.doc`），先运行 `./run.sh convert` 转成同名 `.docx`（或在 WPS / Word 里另存为），再重跑。终端最后也会列出跳过的文件和需处理的文件。
- **一个文件出错不影响其他文件**：损坏或打不开的文件标为「❌ 需处理」并写明原因；Markdown 或附件拆分失败时，脱敏后的 `.docx` 照常输出，报告里有提示。

全部通过、人工检查完，再把 `脱敏文件/` 交出去。**`内部留存-勿外发/` 里有原文，不要外发。**

有任何一个文件「需处理」时，命令以非零状态结束，方便脚本判断。

## 速度

按文件数并行处理（默认使用全部 CPU 核，`--jobs 1` 改为逐个处理），并在终端显示进度和预计剩余时间。实测（4 核 Linux 容器，每份约 500 段正文、带 1 MB 图片）：200 份、212 MB 用时约 5 秒；每份 2.9 MB、内嵌 4.6 MB 字体的真实制度文件，300 份约 11 秒（含生成 Markdown）。耗时主要取决于**文件份数和正文长度**。
